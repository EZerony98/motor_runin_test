# Motor Run-in Test

基于 Python 3.9 和 PySide6 的电机跑合测试上位机。

## 运行

在 PyCharm 中选择项目解释器：

    .venv/bin/python

然后直接运行根目录 main.py。

## 目录职责

- main.py：程序入口和主窗口事件连接。
- ui/：Qt Designer 源文件、生成的界面代码和弹窗。
- drivers/：PLC、仪表、传感器等硬件驱动。
- services/：跑合流程、配置、数据保存和服务器上传。
- workers/：设备读取、测试和上传后台任务。
- models/：产品、设备状态和测试记录数据模型。
- config/：应用、设备、跑合工艺、合格判定和服务器配置。
- utils/：日志、路径和参数校验工具。
- data/：本地测试数据。
- logs/：程序运行日志。
- exports/：报表和数据导出。
- tests/：自动测试。

## 修改界面

使用 Qt Designer 修改 ui/main.ui。保存后通过 PySide6 uic 重新生成
ui/ui_main.py。ui_main.py 是生成文件，不应手工修改。

## 托盘上料与 SN 录入

1. PLC 读取 RFID 后调用 MainWindow.set_tray_id(tray_id) 显示托盘编号。
2. 扫码器按键盘输入方式录入 SN，扫码结束发送回车即可自动跳到下一位置。
   程序兼容 Return、Enter、CR 和 LF，不启用延时自动确认。
3. 只扫描第一个 SN 时，可点击“顺序补齐”生成其余 9 个连续 SN。
4. 点击“保存上料信息”后，程序将托盘号、1～10 坑位和产品 SN 保存到本机
   `data/traceability.db`。产品 SN 不再写入 PLC。
5. 如果已配置频谱电脑映射接口，程序会将本次托盘映射同步到频谱电脑；同步
   失败不会丢失数据，本地批次会保持 `pending` 状态等待重试。
6. 托盘号和 10 个 SN 成功保存后，上位机将“上料信息保存完成”许可
   `%D3000.05` 写为 1；托盘号或 SN 再次被修改时立即撤销许可并写 0。
7. PLC 实体放行按钮 `%D3000.00` 出现上升沿时，程序会先做一次保险保存。
   只有本地保存成功且 `%D3000.05=1` 写入成功后才清空界面；保存或通信失败
   时保留全部录入信息。按钮松开、切换新托盘或程序重新连接 PLC 时写 0。
8. 托盘坑位按实物逆时针编号：下排从左到右为 1～5，上排从右到左为
   6～10；扫码、顺序补齐、PLC结果和数据库坑位均使用这一逻辑顺序。

## PLC 托盘数据映射

- `%D3000.00`：实体放行按钮，只读。
- `%D3000.01`：手动/自动模式，0 为手动，1 为自动；界面点击后取反。
- `%D3000.02`：复位命令，界面按下写 1，松开写 0。
- `%D3000.03`：启动命令，界面按下写 1，松开写 0。
- `%D3000.04`：急停状态，0 为急停中，1 为非急停；界面点击后取反。
- `%D3000.05`：上料信息保存完成/放行许可，保存成功写 1；按钮松开、新托盘、
  数据被修改、程序退出或重新连接 PLC 时写 0。
- `%D3008`：RFID 托盘号，按 INT16 占用 1 个字，只读。
- 产品 SN 不再占用 PLC D 区地址。

顶部设备控制区会持续读取 D3000 的状态并回显。PLC 未连接时所有控制按钮
自动禁用。控制命令使用 FINS DM 位写入，不会因写入一个按钮而覆盖 D3000
中的其他位；程序正常退出前还会主动将复位、启动和上料保存许可恢复为 0。
PLC 放行程序必须将实体按钮 `%D3000.00` 与许可 `%D3000.05` 同时满足作为
放行条件，才能在漏点“保存上料信息”时真正拦住托盘。建议 PLC 在完成一次
放行后也主动清除 `%D3000.05`，避免上位机断线时残留的许可被下一盘复用。

## 四台跑合设备 PLC

- 跑合设备 1～4 的 IP 分别为 `192.168.250.3`～`192.168.250.6`，每台
  使用独立后台线程；测试阶段默认只启用设备 1。
- 四台设备使用相同地址：`DM3008` 是当前卸载托盘号；PLC 结果数组映射基址
  为 `DM1000`，但数组 0 号不属于产品数据，10 个产品实际读取
  `DM1001～DM1060`；`DM3502.00` 是数据可读，`DM3502.01` 是读取完成。
- 每个产品占 6 个 INT，顺序为转速、母板电压、电机温度、电机电流、报警码、
  电机合格标志。前 5 项由 PLC 提供，第 6 项由上位机判定后写回；PLC 不再
  计算或覆盖电机合格标志。1号产品为 `DM1001～DM1006`，2号为
  `DM1007～DM1012`，
  依次递推；起始偏移由 `result_start_offset` 配置，字段顺序后续变化时可通过
  `result_field_order` 调整；
  产品首地址为 `DM1001 + (坑位号 - 1) × 6`。
- PLC 填完托盘号和 10 个产品的前 5 项数据后设置数据可读，并保持托盘号、
  测量值和数据可读位不变。上位机按托盘号和坑位找到 SN，根据 SN 前缀匹配
  型号规则，计算 10 个 OK/NG，再分别写入 `DM1006、DM1012…DM1060` 并
  回读校验。之后在一个 SQLite 事务中保存 10 条结果，全部成功后才将读取
  完成位置 1。PLC 收到读取完成后清除数据可读，上位机再清除读取完成位。
- 界面“跑合数据”页可选择设备，按照逆时针坑位显示最近一盘的 SN、转速、
  母板电压、电机温度、电机电流、报警码及 OK/NG 状态；SQLite 的
  `runin_results` 测量列也使用相同顺序。
- PLC 整数进入上位机时统一换算为实际工程量：转速乘以 2 得到 r/min，
  电压除以 10 得到 V，温度保持 ℃，电流保持 mA。界面显示、规则判定、
  SQLite 保存和后续上传都使用换算后的值。

## 上位机合格判定

- 判定条件位于 `config/quality_rules.json`。程序根据产品 SN 的前缀自动选择
  型号，不需要手动切换；当前先建立 `C68`，匹配前缀为 `C68`。
- 每个型号独立配置 `rule_version`、转速/电压/温度/电流的闭区间上下限以及
  `allowed_error_codes`。规则使用换算后的实际工程量，边界值包含在合格范围
  内。C68 当前允许报警码 0、1，其余报警码均判为 NG。
- 增加型号时，在 `models` 下增加同级对象并设置不重复的 `sn_prefixes`；同一
  SN 未匹配或同时匹配多个型号时，程序拒绝判定和握手确认。
- `configured` 必须为 `true` 且所有 `min/max` 都已填写，程序才允许正式判定。
  C68 已按现场确认范围启用；后续修改标准时应同步更新 `rule_version`。
- SQLite 会保存产品型号、规则版本、判定来源和具体不合格原因，上传队列也
  使用同一份记录，便于后续 PostgreSQL/MES 追溯。

## 两台电脑的追溯同步

- 跑合电脑保存 `tray_cycles`、`tray_products`、`runin_results` 和
  `upload_outbox`。
- 频谱电脑保存托盘映射副本、`spectrum_results` 和独立上传队列。
- `tray_cycle_id` 标识托盘本次流转，避免托盘循环使用后将新产品关联到旧数据。
- 在 `config/server.json` 的 `traceability.spectrum_peer` 中配置频谱电脑的
  IP、端口和令牌。频谱电脑默认监听端口为 8765。
- 两台电脑不能通过网络共享同一个 SQLite 文件；映射通过局域网 HTTP 接口
  同步，两端数据库都保存在各自本机。

## 无 PLC 双机联调

1. 当前配置已启用映射同步：频谱电脑监听 `0.0.0.0:8765`，跑合电脑发送至
   `http://192.168.250.100:8765`，两端联调令牌相同。
2. 首次运行时，在频谱 Windows 电脑允许 Python 通过防火墙，或放行 TCP
   8765；可先在跑合电脑执行
   `Test-NetConnection 192.168.250.100 -Port 8765`。
3. PLC 工程师不在时，可直接在跑合界面手动输入测试托盘号，录入或顺序补齐
   10 个 SN，然后点击“保存上料信息”。日志出现“已同步到频谱电脑”表示发送
   成功；失败数据会保留在本机并每 15 秒重试。
4. 在频谱界面输入完全相同的托盘号并按回车；显示“SN 映射：已匹配
   10/10”即表示接收成功，鼠标停留在状态文字上可查看全部坑位与 SN。
5. 当前仓库中的令牌只用于局域网联调，正式接入公司网络前应改为从环境变量
   读取的独立密钥，不要把正式密钥提交到 Git。

## 开发约定

1. 界面事件只负责收集输入和展示结果。
2. 设备通信统一放在 drivers。
3. 测试流程、数据保存和上传统一放在 services。
4. 耗时操作使用 workers，不阻塞 Qt 主线程。
5. 密码和令牌放在 .env，不提交到 Git。
